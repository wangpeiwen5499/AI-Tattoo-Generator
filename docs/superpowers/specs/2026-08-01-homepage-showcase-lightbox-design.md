# 首页 Showcase + 全屏 Lightbox 设计

> **日期**：2026-08-01
> **状态**：设计已与用户确认，待写实施计划
> **关联**：三个独立产品需求整合实施

---

## 1. 目标

解决用户提出的三个需求：

1. **主页 "See examples" 没有内容** —— 当前是个纯装饰按钮，点击无反应。
2. **图片悬浮展示太小** —— 生成结果 / 历史里的图片弹窗是 `max-w-3xl` 卡片，要改成"占满浏览器"的全屏图片浏览。
3. **落地页展示纹身效果图** —— 首页加 showcase 区做转化；用无脸身体照生成，避免人脸等敏感信息。

---

## 2. 现状

| 需求 | 现状 |
|---|---|
| 1 | `src/app/page.tsx:36-38` 的 `<Button variant="outline">See examples</Button>` 无 `onClick` / `href`，纯装饰 |
| 2 | 两处图片弹窗共用 shadcn `DialogContent`（`src/components/ui/dialog.tsx`），都加 `max-w-3xl`：生成结果 `src/components/generation-results.tsx`、历史 `src/components/history-image-dialog.tsx`。底层是"居中卡片"模式（rounded + ring + 居中），不支持全屏 contain |
| 3 | 首页 `page.tsx` 目前只有 hero +（signed-in: TattooGenerator / signed-out: 两个按钮），**无 showcase 区** |

---

## 3. 已确认的设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| showcase 图来源 | **预备精选示例**（KIE 生成） | 零隐私风险、质量可控、无需 consent 机制 |
| 脱敏方式 | **源头避免**：输入用无脸局部身体照（只拍手臂/腿/肩，不含头） | 比后处理打码更干净；融合输出自然无脸 |
| 无脸身体照源 | **Unsplash 免费图库**（用户选定） | 免费商用、图源丰富、无需用户自己拍 |
| showcase 展示内容 | 纹身**上身效果**融合图（3:4 竖图） | 产品核心卖点（看到纹身在身上的样子） |
| showcase 布局 | **紧凑 3 列网格**，6–9 张，hover 微放大，点击进 Lightbox | 信息密度高、让图说话 |
| showcase 放置 | 首页 hero 下方，**仅 signed-out 显示** | 落地页转化用；已登录用户直接进生成器 |
| "See examples" 按钮 | 改成 `<Link href="#examples">` 锚点滚动到 showcase | 让原装饰按钮有去向 |
| Lightbox | **新建统一全屏组件**，三处复用 | 全屏 lightbox 与卡片 Dialog 是不同交互模式，独立组件更清晰 |

## 4. 改动 A：统一 `<Lightbox>` 全屏组件（需求 2）

### 4.1 组件接口

新建 `src/components/lightbox.tsx`（'use client'）：

```ts
export type LightboxImage = { url: string; alt: string }

interface LightboxProps {
  images: LightboxImage[]
  /** 当前展示的图片索引；null 表示关闭 */
  index: number | null
  onClose: () => void
  onIndexChange: (i: number) => void
}
```

受控组件（`index` 由父组件管理），与现有 `HistoryImageDialog` 的 `openIndex` 模式一致，便于三处接入。

### 4.2 行为

- **全屏深色**：`fixed inset-0 z-50`，背景 `bg-black/90`；图片 `object-contain max-h-full max-w-full` 居中（完整显示不裁剪——这是"占满浏览器图片浏览"的核心）。
- **关闭方式**：右上 X 按钮、点击图片外区域（背景）、`Esc` 键。
- **切换**（`images.length > 1` 时）：左右箭头按钮（固定在视口左右中）、`←` / `→` 键、底部居中 `N / M` 计数。循环切换（与现有 HistoryImageDialog 一致：`(i ± 1 + len) % len`）。
- **可访问性**：`aria-label`（Previous/Next/Close）、`role="dialog"`、`Esc` 关闭、打开时聚焦管理。

### 4.3 底层技术

用 base-ui `Dialog` primitive（`@base-ui/react/dialog`，已被 shadcn `ui/dialog.tsx` 使用）拿 `Portal` / `Backdrop` / `Esc` 关闭 / 聚焦陷阱，但 **不复用 `DialogContent`**（它是卡片模式）。Lightbox 自己组合 `Dialog.Root/Portal/Backdrop/Popup`，把 Popup 样式覆盖成全屏。

> 不用 `DialogContent` 的原因：它的默认类（`rounded-xl bg-popover p-4 ring` + 居中 `max-w-sm`）是卡片语义；强行用 className 覆盖成全屏会让组件臃肿、易出错。Lightbox 直接用 primitive 更干净。

### 4.4 三处接入

| 调用方 | 现状 | 改造 |
|---|---|---|
| `GenerationResults` | `zoom` state（单图，无切换） | 改为 `lightboxIndex` state + `images = [设计稿, ...成功部位]`，支持切换。替换现有 `<Dialog>` |
| `HistoryImageDialog` | `openIndex` state + `<Dialog>` | state 逻辑保留（含 `bodyPartDialogIndex` 映射），容器换成 `<Lightbox>` |
| `Showcase`（新） | — | `selectedIndex` state + 全部示例图，点击进 Lightbox 串联切换 |

## 5. 改动 B：首页 Showcase 区（需求 1 + 3）

### 5.1 文件结构

- `src/lib/showcase-examples.ts` —— 纯数据：`{ key: string; alt: string }[]`（key 如 `'showcase/dragon.png'`）。**不依赖 env / R2 SDK**，Client Component 也能 import。
- `src/components/showcase.tsx`（'use client'）—— props `{ images: { url: string; alt: string }[] }`，渲染 3 列网格 + 内置 `<Lightbox>`，state 管当前 index。
- `src/app/page.tsx`（Server Component）—— import `SHOWCASE_EXAMPLES` + `getPublicUrl`，map 成 `{ url, alt }` 传给 `<Showcase>`；仅在 signed-out 渲染。

> URL 解析放 Server 端（page.tsx）：`getPublicUrl` 用 `process.env.R2_PUBLIC_URL`，且 `lib/r2.ts` import 了 `@aws-sdk/client-s3`，不能进 Client bundle。Client `Showcase` 只接收已解析的 URL 字符串。

### 5.2 布局

- `<section id="examples">` 放在 hero 下方、signed-out 区块内。
- 网格：`grid grid-cols-3 gap-3 sm:gap-4`，每张图 `aspect-[3/4] object-cover`，hover `scale-[1.02]` 微放大，`cursor-zoom-in`。
- 6–9 张（初始 8 张：见 §6 prompt 列表）。
- 标题区：`<h2>Real tattoo previews</h2>` + 一句副标题（如 "Generated by AI · click to enlarge"）。
- `scroll-margin-top: 5rem`（避免锚点滚动时被 64px sticky navbar 遮挡）。

### 5.3 "See examples" 按钮

`page.tsx:36-38` 改为：
```tsx
<Button size="lg" variant="outline" render={<Link href="#examples" />}>
  See examples
</Button>
```
> 用 base-ui 的 `render` prop（shadcn/Button 基于 base-ui）把 Button 渲染成 Link，保留按钮样式同时获得锚点跳转。配合 `html { scroll-behavior: smooth }`（加到 `globals.css`）实现平滑滚动。

### 5.4 signed-in 行为

不变：signed-in 仍渲染 `<TattooGenerator />`，不显示 showcase（showcase 整个在 `<Show when="signed-out">` 内）。

## 6. 示例图生成（实施前置依赖）

### 6.1 脚本

新建 `scripts/gen-showcase.mjs`（参考现有 `scripts/verify-day3.mjs` 模式，`node --env-file=.env.local`）：
- 读取一组 prompt + 对应的无脸身体照 URL。
- 对每个 prompt：调 KIE `createTask`（image-to-image，`aspect_ratio: 3:4`）→ 轮询 → 下载到 R2 key `showcase/<slug>.png`。
- 复用 `apply-to-body.ts` 里的单部位逻辑（每 prompt 出 1 张上身图，不是 4 部位）—— 抽一个 `generateSingleFusion({ bodyPhotoUrl, prompt })` 辅助函数供脚本和（未来）其他单图场景复用。
- 生成完打印 8 个 R2 public URL，供人工核对。

### 6.2 无脸身体照源（Unsplash）

从 Unsplash 选 8 张（或少量身体照复用到多个 prompt），选取标准：
- **无脸**：构图只含手臂 / 小腿 / 肩 / 背局部，**不含头部**。
- **适合贴纹身**：皮肤面积足够、光照均匀、背景不杂乱。
- **多样性**：不同肤色 / 部位。
- **许可**：Unsplash License（免费商用，无需授权）。

> 下载后上传到 R2 `showcase/body/` 作为脚本输入（可控、不依赖 Unsplash CDN；KIE `input_urls` 用 R2 public URL）。

### 6.3 Prompt 列表（8 个经典纹身题材）

## 7. 边界 / 错误处理

| 场景 | 处理 |
|---|---|
| Lightbox 图片加载失败 | 该图位置显示占位（muted bg + 图标），不阻塞切换 |
| Lightbox `images` 为空 | 不渲染 / 不打开 |
| showcase 某 URL 失效 | 该格降级占位（`<div>` muted bg），其余正常 |
| 示例图尚未生成（R2 无 `showcase/*.png`） | img broken 时浏览器显示 alt + 容器 `bg-muted` 兜底，不崩；图生成后自然恢复。`SHOWCASE_EXAMPLES` 硬编码非空，无需"为空隐藏"分支 |
| 脚本生成中途失败 | 单 prompt 失败不阻塞其他；失败的 slug 在数据文件里可先注释掉 |

## 9. 非目标（YAGNI）

- 不做 showcase 后台管理（DB 表 / admin）：MVP 硬编码足够，常换再加表。
- 不做用户作品 consent 展示机制：用预备示例规避，不碰真实用户数据。
- 不做图片缩放 / 旋转 / 下载：Lightbox 只负责浏览 + 切换。
- 不做 showcase 懒加载 / 分页：8 张图直接渲染。
- 不动 signed-in 首页（生成器）。
- 不做"人脸检测自动打码"管线：源头用无脸身体照，无需后处理。
