# 生产问题修复设计

依据：2026-10-29 项目分析及用户“开始进行修复”的授权。

目标：修复身份冒用、遗留公开接口、并发计费、生成中断、网站地图及误导反馈。

约束：沿用 Next.js / Drizzle / PostgreSQL / KIE / R2；不变更套餐价格，不操作生产数据，不推送或部署。

实施选择：

- 游客使用 AUTH_SECRET 签名、有期限、限定 guest UUID 格式的 Cookie；旧未签名 Cookie 失效，上传时重新发放。
- 遗留测试发信接口关闭；通用上传要求登录并限制大小、数量与图片格式；文件代理仅允许受信存储来源，拒绝重定向。
- 积分消费锁定用户后执行，扣不足必须回滚；订单入账先锁订单。退款关联消费记录，以事务保证只退一次，游客不发退款积分。
- 新建 tattoo_job 保存 AI 子任务 ID、阶段、租约、消费记录和期限。启动、状态查询、受保护的定时接口都可推进短步骤；不在请求中长轮询。外部创建超时不盲目重试，避免重复收费。
- 部分生成失败时仍展示成功图片，但返还整个付费积分；仅全部四张成功才保留扣费。退款到账由服务端真实记录确认。
- 上传 key 必须属于当前身份，URL 由服务端构建，并检查实际对象存在、类型和大小。
- 保持现有游客每 IP 每 UTC 日三次规则并统一文案。私有页面明确 no-store。
- 添加可重复运行、无真实外部付费调用的回归测试；数据库验证使用本地内存 PostgreSQL。

交付：代码、增量数据库升级脚本、环境配置示例、部署与验证说明。部署前必须先运行数据库升级；本次不访问生产数据库。
