本次为本地代码修复，未访问生产数据库，未推送或部署。2026-10-29，起点 ab073cc，分支 fix/production-hardening。

## 改动与业务约定

- 游客 Cookie 需 AUTH_SECRET 签名，有效期 30 天。仅用于读取历史游客结果，不再签发新游客身份。
- 游客只能体验真实交互案例，不可上传或真实生成。新账户一次性赠送 3 个永久积分，邮箱验证后可用；老账户登录不重复领取。注册 IP 每 UTC 日最多创建 10 个账号；已验证登录用户每 IP 每天最多上传 100 次。
- 每次成功产生完整 4 部位才保留扣费；任一部位失败会在结果落库的同一事务中退还原积分，保留成功图片。
- 退款恢复原始 grant，保留原有效期，并将消费记录标为 deleted，防止重复退款。
- 新 tattoo_job 保存请求 ID、KIE 任务 ID、状态、租约、截止时间和消费记录。启动重试使用相同 requestId 只扣一次；每个身份最多一个在途任务。
- 单次推进只执行一个有界步骤。创建外部任务前持久化提交意图；若进程在返回任务 ID 前中断，该任务不会被自动重新创建，避免重复计费。可能已发生的供应商费用由服务方承担。
- 部分临时查询/下载错误可重试。任务总期限 20 分钟，前端轮询最长 21 分钟；超期由后续轮询或定时推进终结和退款。
- 退休的模板邮件测试接口返回 410；真正验证码邮件仍由 Better Auth 发送。
- 文件代理只允许 R2_PUBLIC_URL / FILE_PROXY_ORIGINS 中的精确 HTTPS 来源，拒绝重定向。通用上传要求登录且邮箱已验证，限制大小、数量、文件签名。
- 用户照片仍通过公共存储链接供 AI 读取。此次不更改存储桶权限；已在上传处和隐私文案明确第三方处理及持链可访问。迁移私有存储和历史图片保留策略应单独处理。

## 1. 配置与数据库升级（先于代码切换）

GitHub 自动部署现在会先运行 `npm run deploy:prepare`：仅在 Vercel production 环境检查认证、存储、AI 和邮件设置，并执行以下幂等增量升级；缺项或升级失败会停止新部署，保留当前线上版本。preview 和本地构建不会连接生产数据库。以下命令仍可用于预演与手动升级。任务调度继续按第 2 节单独配置。

1. 备份数据库，在测试库先执行升级。升级工具默认只输出 SQL，不连接数据库。
2. `npm run db:upgrade:tattoo-jobs`
3. 确认 DATABASE_URL 指向目标环境，执行 `npm run db:upgrade:tattoo-jobs -- --apply`。
4. 工具在事务中使用 advisory lock，只创建 tattoo_job 和索引，并添加 guest_free_usage.upload_count；可重复执行。不重建旧表、不删除记录。
5. 配置 RESEND_API_KEY 和 RESEND_SENDER_EMAIL（缺少配置时邮箱注册返回 503，避免创建无法验证的账号）；新账户创建与赠送积分在同一事务中完成。旧 INITIAL_CREDITS_* 配置不再控制纹身注册赠礼。配置 AUTH_SECRET（至少 32 字符，沿用现有有效值）、R2、KIE、CRON_SECRET。环境示例列出完整名称。
6. Waffo 产品 ID 当前来自 `src/config/locale/messages/{en,zh}/pages/pricing.json` 的 payment_product_id，两种语言需一致；WAFFO_PRODUCT_* 当前不参与 checkout。

新开发库可用 db:push 建立完整 schema；已有生产库请使用上面的增量工具。

## 2. 配置定时推进（上线必需）

页面打开时，状态轮询会自动推进任务。页面关闭后，需要独立调度器继续推进与处理超时退款。

- 调度器 GET `https://tattoovis.ink/api/internal/tattoo-jobs`
- Header：`Authorization: Bearer <CRON_SECRET>`
- 至少每分钟一次，建议每 10–30 秒一次；每次并行处理最多 5 个到期任务，单次函数上限 60 秒。流量增大时需提高调度频率或容量。
- 在支持分钟级 Cron 的 Vercel 套餐上，可在 vercel.json 的 crons 加入 `{ "path": "/api/internal/tattoo-jobs", "schedule": "* * * * *" }`；Vercel 会使用 CRON_SECRET。
- 套餐未确认，因此本次没有自动添加 Cron 或改变套餐。也可由外部调度器调用同一受保护接口。
- 验证不带凭据返回 401；正确凭据返回 `{ advanced: N }`。该值是取得候选任务数，不代表全部已完成。
- 未配置调度器时，刷新生成页可恢复任务，但无人查看时不会自行完成，也不会准时退款。

部署前请按当前 Vercel 文档核对套餐调度限制：https://vercel.com/docs/cron-jobs/usage-and-pricing

## 3. 验证清单

- 安全：伪造/旧 guest_id 拒绝；游客上传及生成返回 401；未验证用户返回 403；跨用户图片 key 拒绝，bodyPhotoUrl 不被信任。
- 上传：有效 JPG/PNG/WebP 可直传；超 10MB、伪造类型、超预算拒绝；实际对象由 HEAD 和前缀读取校验。
- 生成：正常流程生成设计 + 4 张预览；刷新页面继续；重复 requestId 不重复扣分；在途任务禁止另开。
- 故障：设计失败、部分失败、查询临时失败、外部提交中断、超过总期限；成功图片保留，付费积分最多退一次。
- 计费：真实隔离 PostgreSQL 用至少两条连接并发消费最后一个积分、重放支付通知和失败退款。PGlite 测试不能替代此项。
- 支付：在 Waffo 测试环境验证套餐、metadata、整数美分入账，含税订单的 subtotal/total，以及 webhook 重试。
- 页面：/sitemap.xml 使用实际域名；/history 和 /zh/history 响应 private,no-store；历史列表分页。
- 回归：npm test、npm run typecheck、npm run lint、npm run build。

## 4. 旧任务、回滚与遗留项

- 旧 processing 项目没有 KIE 任务 ID，也没有可靠关联的消费记录，无法自动恢复/推断退款。上线前人工核对这些记录；本次升级不会批量修改或补发积分。
- 回滚代码可保留新增表和列；不要为回滚删除业务数据。旧代码不理解签名游客 Cookie，回滚后游客需清除该 Cookie / 重新建立会话。
- eslint-baseline.json 记录 72 项原模板错误，npm run lint 只允许这些既有指纹，新增错误会失败。模板代码全面清理不包含在本次生产修复中。
